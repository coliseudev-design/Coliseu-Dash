================================================================================
PROMPT DE ENGENHARIA: AJUSTE DO WORKER C# (COLISEUSALES.WORKER)
Inclusão de DESCONTO_ITEM na View DASH_VENDAS_ITENS do Firebird e Sincronização
================================================================================

Você é um Desenvolvedor C# / .NET e Engenheiro de Banco de Dados Firebird especialista na arquitetura do ColiseuSales.Worker.

--------------------------------------------------------------------------------
1. CONTEXTO E OBJETIVO
--------------------------------------------------------------------------------
No sistema de Dashboard/BI, os rankings de Produtos, Marcas e Categorias estavam com divergência em relação ao relatório "Posição de Pedidos - Resumido" do ERP FAC.

Causa Raiz Identificada:
- O relatório do ERP calcula o valor líquido de cada item usando o percentual de desconto INDIVIDUAL do item (PEDIDO_ITENS.DESCONTO).
- A view DASH_VENDAS_ITENS no Firebird extraía apenas o valor bruto (VALOR_TOTAL) sem a coluna de desconto do item.
- Exemplo real: Pedido 680881 - Produto EUCALIPTO TRATADO tem valor bruto de R$ 49.411,04 com desconto de 30.7%, totalizando líquido de R$ 34.226,00 no ERP.

Objetivo da Tarefa:
Atualizar a criação da view DASH_VENDAS_ITENS no FirebirdBootstrapper do Worker para incluir o campo DESCONTO_ITEM, garantindo que o Worker envie esse valor em todas as sincronizações para o Dashboard Middleware.

--------------------------------------------------------------------------------
2. ARQUIVOS A ALTERAR NO WORKER
--------------------------------------------------------------------------------

Arquivo: worker/ColiseuSales.Configurator/FirebirdBootstrapper.cs (ou onde as views DASH_* são gerenciadas)

Localize a definição de DASH_VENDAS_ITENS e adicione a linha:
    COALESCE(pi.DESCONTO, 0) AS desconto_item,

Código atualizado da View:

CREATE OR ALTER VIEW DASH_VENDAS_ITENS AS
SELECT
    ((pi.ID_PEDIDO * 1000) + pi.ID_ITEM)                                        AS id_firebird,
    pi.ID_PEDIDO                                                                AS venda_id_firebird,
    pi.ID_PRODUTO                                                               AS produto_id_firebird,
    (CASE WHEN nat.TIPO = 2 THEN -1 ELSE 1 END) * COALESCE(pi.QTDE, 0)          AS quantidade,
    COALESCE(pi.VALOR_UNITARIO, 0)                                              AS preco_unitario,
    COALESCE(pi.VALOR_CUSTO, 0)                                                 AS custo_unitario,
    (CASE WHEN nat.TIPO = 2 THEN -1 ELSE 1 END) * COALESCE(pi.VALOR_TOTAL, 0)    AS valor_total,
    COALESCE(pi.DESCONTO, 0)                                                    AS desconto_item,
    COALESCE(f.NOME, '')                                                        AS vendedor,
    COALESCE(pr.DESCRICAO, '')                                                  AS produto,
    COALESCE(pr.MARCA, '')                                                      AS marca,
    COALESCE(cat.DESCRICAO, '')                                                 AS categoria,
    p.ID_DEPTO                                                                  AS depto_id,
    p.ID_NATUREZA                                                               AS natureza_id,
    nat.TIPO                                                                    AS natureza_tipo,
    nat.PROCESSO                                                                AS natureza_processo
FROM PEDIDO_ITENS pi
JOIN PEDIDOS p ON p.ID_PEDIDO = pi.ID_PEDIDO
LEFT JOIN PRODUTOS pr ON pr.ID_PRODUTO = pi.ID_PRODUTO
LEFT JOIN CATEGORIAS cat ON cat.ID_CATEGORIA = pr.ID_CATEGORIA
LEFT JOIN FUNCIONARIOS f ON f.ID_FUNCIONARIO = p.ID_VENDEDOR
LEFT JOIN NATUREZA_OPERACAO nat ON nat.ID_NATUREZA = p.ID_NATUREZA
WHERE p.STATUS IN (0, 1, 2, 9)
  AND p.TIPO = 1
  AND nat.OPERACAO IN (1, 6, 12)
  AND (nat.PROCESSO <> 3 OR nat.PROCESSO IS NULL);

--------------------------------------------------------------------------------
3. VERIFICAÇÃO DO JOB DE SINCRONIZAÇÃO
--------------------------------------------------------------------------------

Arquivo: worker/ColiseuSales.Worker/Jobs/SyncDashboardDataJob.cs

No método SyncVendasItensAsync, certifique-se de que a query continua:
    SELECT * FROM DASH_VENDAS_ITENS ORDER BY venda_id_firebird DESC

Como o Worker usa QueryRawAsync com dicionário/json dinâmico, o novo campo "desconto_item" será serializado e enviado automaticamente no payload HTTP POST para /internal/sync/dash_vendas_itens.

--------------------------------------------------------------------------------
5. CRITÉRIO DE ACEITE / VALIDAÇÃO
--------------------------------------------------------------------------------
1. O Worker deve compilar com sucesso sem erros de build (`dotnet build`).
2. Ao inicializar o Worker, o Bootstrapper deve criar/atualizar a view DASH_VENDAS_ITENS.
3. No Firebird, a query:
   SELECT FIRST 5 PRODUTO, VALOR_TOTAL, DESCONTO_ITEM,
          VALOR_TOTAL * (1 - DESCONTO_ITEM / 100.0) AS VALOR_LIQUIDO
   FROM DASH_VENDAS_ITENS WHERE DESCONTO_ITEM > 0;
   deve retornar o valor líquido exato de cada item.
4. O ciclo de sync deve rodar sem erros e enviar os registros com a coluna desconto_item preenchida.
